# 日曆資料可靠性：本輪交付

本輪實作上一輪待辦的第 1 項（日曆資料可靠性），沒有宣稱完整邀約／Google MVP 已可放行。

## 已實作

- 行程及截止事項先保存帳號專屬待同步請求，再傳送 API。成功讀取遠端資料時仍合併待同步內容，重新啟動可恢復。
- 同帳號的保存、修改、取消、載入及重送排隊執行；重複重送共用進行中的工作。網路等待最多 15 秒，離線重送遇到第一個網路失敗就停止本批。
- 建立請求沿用固定冪等鍵與原始內容。收到回覆前修改的草稿，重播建立後套用最新修改；取消採保留取消記錄直到伺服器確認。遺失新增、修改或刪除回應後重試不另建事件。
- POST 重播包含已刪除的紀錄；DELETE 已刪除紀錄視為成功。事件 PATCH 不再清掉原始冪等鍵。GET 單筆資料支援本人本機識別碼，供 409 後明確重新載入。
- 草稿衝突保留輸入、顯示錯誤；使用者重新載入並確認儲存後解除待同步項目。同步中的草稿已轉成遠端資料時，不會讓舊編輯畫面誤刪或靜默丟棄修改。
- 啟動、回到前景、手動刷新及前景每分鐘重試草稿；Google 自動同步沿用五分鐘節流。
- 外部來源載入失敗保留 Google 快取；顯示待同步筆數、來源失敗與上次完整更新時間。401 不回傳其他帳號快取。
- 帳號切換重建日曆 repository，進行中的工作固定使用原帳號範圍。登出清除已同步快取，保留隔離的待同步草稿；邀約快取清除也不再移除邀約草稿。
- 行程與截止事項表單儲存期間防重送，成功才關閉；失敗保留文字，409 要先明確重新載入才能再送出。修正編輯起訖日期使用 UTC 日期造成的偏移。

## 真機驗收流程

1. 已登入且曾載入自己的日曆來源後，開啟飛航模式，新增一筆行程與截止事項；確認顯示待同步。
2. 結束 App 再開，確認兩筆仍在；修改其中一筆並取消另一筆。
3. 恢復連線，按重新整理；確認只建立修改後的一筆，取消項目不再出現。
4. 登出再登入同帳號確認待同步資料仍在；換另一帳號確認看不到前一帳號的內容。
5. 兩台裝置編輯同筆資料，確認 409 保留輸入、要求重新載入，並由使用者再次確認儲存。
