# 約飯網頁與 App 同步

更新：2026-09-26。使用者確認網頁只提供「約時間吃飯」，完整 Calendar／Planner／Deadline 仍由 App 承載。

## 網頁入口

- `/`：登入、進行中／已結束飯局、建立飯局。無後端設定時明確顯示未連接，不提供假飯局。
- `/gatherings/[id]`：本人已加入飯局的完整詳情，含分享、草稿／提交、推薦、主揪拍板／取消、本人加入 App 日曆。
- `/join/[token]`：公開摘要、Google 登入並返回、明確加入確認，加入後共用上述詳情。
- `/coordinate`：相容舊 gathering／invite 連結；`/calendar` 回到飯局首頁。既有 Planner 原始碼保留，網頁不再以其作為入口。

## 同步契約

Web 與 App 使用同一個 Supabase 使用者及 `/api/v1/coordination` 業務服務，沒有第二份網頁日曆。

1. App 已上傳的行程與 Google 已同步的事件，由本人「取得最新日曆狀態」讀取。App 尚未上傳的離線草稿不可被網頁讀取。
2. 日曆只傳狀態差異：App/busy 為不行，tentative 為待確認，free 不占時間，沒有事件維持未填，Deadline 不納入。
3. 預設勾選未填格；覆蓋既有選擇需明確勾選。確認後只寫本人草稿，不自動正式提交。
4. 預覽後日曆狀態若改變，API 回 409，要求重新取得差異。草稿版本也由服務端核對。
5. 拍板後本人按「加入我的 App 日曆」呼叫共用的冪等日曆操作。同帳號 App 刷新後顯示，不會寫入其他人的日曆，也不會寫回 Google。

同步是共用雲端資料與明確刷新，不宣稱背景即時同步。Google 登入不等於授予 Google 日曆權限。
